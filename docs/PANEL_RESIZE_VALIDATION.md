# GNOME Shell 42 패널 높이 조절 검증

이 안내는 `아기다리고기다리` 브랜치의 패널 높이 조절과 관련 리팩토링을 대상 GNOME 환경에서 검증하기 위한 절차입니다. Node 테스트는 상태·정리·계산을 검증하지만 St의 실제 배치, 화면 배율, IME, Shell의 포인터 grab을 대체하지 않습니다.

## 준비

실제 사용 환경과 같은 GNOME Shell 42에서 변경된 체크아웃을 준비합니다. 먼저 다음 명령을 프로젝트 루트에서 실행합니다.

```sh
gnome-shell --version
bash src/scripts/test.sh
bash src/scripts/test.sh --sockets
```

개발 의존성을 설치한 환경에서는 `npm run format:check`도 실행합니다. 확장 설치는 기존 절차인 `bash install.sh`를 일반 데스크톱 사용자로 실행합니다. X11은 `Alt+F2` → `r`로 Shell을 다시 시작하고, Wayland는 로그아웃 후 다시 로그인합니다. 세션 재시작 전에 편집 중인 내용을 저장합니다.

오류 로그는 별도 터미널에서 확인합니다.

```sh
journalctl --user -f -o cat
```

## 기본 레이아웃 보존

Appearance의 **Reset panel heights**로 네 패널의 높이를 자동으로 되돌립니다. 같은 설정·데이터에서 기존 화면과 비교합니다.

- 메인 메뉴의 너비, 여백, 영역 순서와 접힘 상태가 유지되는지 확인합니다.
- 채팅·메모·서비스 패널을 여러 순서로 열고, 메인 패널 가까이 오는 순서와 간격이 유지되는지 확인합니다.
- 짧은 목록은 기존처럼 자연 높이로 표시되고, 긴 목록은 기존 내부 스크롤을 사용하는지 확인합니다.
- 밝은/어두운 테마, 애니메이션 켜짐/꺼짐, 자동 스크롤바 설정에서 배경·모서리·스크롤바가 깨지지 않는지 확인합니다.

## 패널별 조절

상단 바에서는 아래쪽 가장자리와 양 모서리, 하단 바에서는 위쪽 가장자리와 양 모서리를 사용합니다. 각 패널을 따로 늘리고 줄입니다.

| 대상 | 확인할 내용 |
| --- | --- |
| 메인 | 메뉴 순서가 유지되고, 짧게 만든 경우 모든 항목에 스크롤·키보드로 접근 가능 |
| 채팅 | 대화 영역이 크기를 받아 사용하며 입력창·전송·연결 버튼이 잘리지 않음 |
| 메모 | TODO/Note 전환, 긴 줄, 편집기 열기·닫기, 저장·취소 버튼에 접근 가능 |
| 서비스 | 카드 목록이 크기를 받아 사용하며 헤더와 닫기 버튼에 접근 가능 |

드래그 중에는 다른 패널의 높이·너비가 바뀌지 않아야 합니다. 포인터를 패널 밖으로 이동한 뒤 버튼을 놓아도 드래그가 끝나야 합니다. 가장자리를 벗어나면 커서가 정상으로 돌아와야 하며, 입력창 선택·스크롤바 드래그·버튼 클릭은 기존처럼 동작해야 합니다.

## 취소와 저장

1. 기존 높이에서 드래그를 시작하고 `Esc`를 누릅니다. 원래 높이로 돌아가고, 이후 마우스 버튼을 놓을 때 아래 버튼이 눌리지 않아야 합니다.
2. 정상 드래그 후 팝업을 닫았다 다시 엽니다. 마지막 높이가 유지돼야 합니다.
3. 확장을 껐다 다시 켭니다. 패널별 높이가 유지돼야 합니다.
4. Appearance에서 한 패널의 숫자만 바꿉니다. 해당 패널만 갱신돼야 합니다.
5. 한 패널을 `0`으로 설정합니다. 해당 패널만 자동 크기로 돌아가야 합니다.
6. **Reset panel heights**를 누릅니다. 네 높이만 초기화되고 여백·간격·테마 등은 유지돼야 합니다.

## 경계와 수명 주기

- 패널을 화면보다 크게 늘리려 해도 사용 가능한 화면 높이를 넘지 않아야 합니다.
- 작은 모니터로 옮겼다가 다시 큰 모니터로 돌아옵니다. 표시 높이는 제한되지만 저장한 희망 높이는 유지돼야 합니다.
- 화면 배율과 해상도를 바꾸고 다시 엽니다. 새 화면의 경계를 적용해야 합니다.
- 작은 화면에서 메모 편집기·채팅 연결 영역을 모두 열어도 필요한 버튼까지 스크롤로 접근할 수 있어야 합니다.
- 드래그 도중 패널을 숨기거나 확장을 비활성화한 뒤 다른 창을 클릭합니다. 포인터 grab과 크기 조절 커서가 남지 않아야 합니다.
- 팝업을 빠르게 열고 닫거나 사이드 패널을 연속 토글해도 높이·모서리·입력 포커스가 깨지지 않아야 합니다.
- 한글 조합 입력, 메모 커서 이동, 키보드 메뉴 탐색 시 현재 입력 위치가 보이는지 확인합니다.

## 이모지·입력 후보창 겹침

### 보고된 환경: X11, Ctrl+E 시스템 이모지창

이번 가림 증상의 재현 환경은 X11이며, 시스템 이모지 단축키는 `Ctrl+E`입니다. 이 경로에서는 별도 GTK 이모지 팝업이 사용하는 상위 팝업 레이어 아래로 핑구스 메뉴를 배치합니다. 단축키를 가로채거나 다시 등록하지 않으며 기존 시스템 설정을 사용합니다.

1. `echo $XDG_SESSION_TYPE`이 `x11`인지 확인하고, 채팅 입력창에 초안을 작성합니다.
2. `Ctrl+E`로 시스템 이모지창을 엽니다. 창이 핑구스 패널에 가려지지 않아야 합니다.
3. 평소 사용하는 방식으로 이모지를 검색하고 방향키·Enter로 선택합니다. 선택한 이모지가 기존 초안의 입력 위치에 삽입돼야 합니다.
4. 다시 열고 `Esc`로 취소합니다. 채팅 초안과 입력 포커스가 유지돼야 합니다.
5. 채팅 패널의 높이를 늘려 이모지창과 겹치게 한 뒤 반복합니다. 핑구스 팝업을 닫았다 다시 연 경우와 확장을 껐다 켠 경우도 확인합니다.

이 변경에서 X11의 별도 GTK 이모지창은 **표시 순서와 기존 키보드 입력 경로**가 대상입니다. GTK 창의 마우스 선택은 Shell 메뉴가 포인터를 잡는 별도 문제이며, 이 변경으로 해결됐다고 간주하지 않습니다.

### 다른 입력 후보창과 회귀 확인

채팅 입력창에 초안을 작성한 상태에서 사용하는 시스템 이모지 단축키로 후보창을 엽니다. GNOME/IBus 설정에 따라 단축키가 다를 수 있습니다.

- 입력 후보창이 핑구스 패널 앞에 표시되는지 확인합니다. 채팅 패널을 크게 늘려 후보창과 겹치게 한 경우도 확인합니다.
- Shell 내부 후보 목록에서 마우스로 후보를 선택하거나 페이지를 넘겨도 핑구스가 바깥 클릭으로 닫히지 않고 선택한 글자가 입력돼야 합니다.
- 키보드로 검색·선택·취소한 뒤 기존 초안과 입력 커서가 유지되는지 확인합니다.
- 후보창이 없는 상태의 바깥 클릭과 메뉴 닫기, 높이 조절 드래그, 다른 모달 창의 입력 차단이 기존처럼 동작해야 합니다.
- 확장을 껐다 켠 뒤 반복 확인하고, 다른 앱의 입력 후보창이나 스크린샷 UI가 영향을 받지 않는지 확인합니다.

GNOME Shell 내부 후보창과 별도 GTK 이모지 창은 다른 경로입니다. 이 변경은 핑구스 메뉴를 네이티브 팝업·시스템 입력 레이어 아래로 배치하고, Shell 내부 후보에 한해 포인터 이벤트를 전달합니다. X11의 GTK 팝업은 상위 팝업 레이어를 사용하므로 표시 순서는 복구되지만, Shell 메뉴의 포인터 grab이 유지되므로 GTK 창의 마우스 선택까지 해결하는 변경은 아닙니다. Wayland의 별도 GTK 카테고리 창은 일반 창으로 표시될 수 있어 이 변경만으로는 가려짐이 해결되지 않습니다. 해당 경로와 별도 이모지 앱의 동작은 실제 사용 환경에서 추가 확인해야 하며, 이 변경은 외부 앱의 포커스나 grab을 강제로 바꾸지 않습니다.

실패를 기록할 때는 GNOME 버전, X11/Wayland, 상단/하단 바 위치, 화면 해상도·배율, 패널 이름, 저장된 높이, 재현 순서와 해당 시각의 오류 로그를 함께 남깁니다. Intra 쿠키나 토큰은 로그에 포함하지 않습니다.
