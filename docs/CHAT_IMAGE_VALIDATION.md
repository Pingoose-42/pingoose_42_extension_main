# GNOME Shell 42 채팅 이미지·나에게 보내기 검증

이 문서는 Ubuntu의 실제 GNOME Shell 42 세션에서 이미지 첨부와 자기 자신에게 보내기를 확인하기 위한 절차입니다. 자동 검사는 데이터 검증·소켓 전송·취소 상태를 확인하지만, 실제 GTK 파일 선택창의 포커스와 Shell 패널 배치를 대신하지 않습니다. 각 항목은 실행 후 통과·실패·미실행으로 기록합니다.

## 환경과 준비

현재 사용 환경인 **X11**에서 먼저 실행합니다. Wayland를 지원 대상으로 배포한다면 같은 절차를 별도로 실행하고 결과를 구분합니다. 패널의 기본 동작은 [패널 높이·테마 검증](PANEL_RESIZE_VALIDATION.md)과 함께 확인합니다.

```sh
gnome-shell --version
echo "$XDG_SESSION_TYPE"
bash src/scripts/test.sh
bash src/scripts/test.sh --sockets
```

개발 의존성이 설치되어 있으면 `npm run format:check`도 실행합니다. 변경된 체크아웃을 기존 설치 절차로 설치하고 새 스키마와 worker 파일까지 반영합니다. X11에서는 작업을 저장한 뒤 `Alt+F2` → `r`, Wayland에서는 로그아웃·로그인으로 확장을 다시 불러옵니다.

다음 상대와 파일을 준비합니다.

- 이미지 기능이 있는 다른 PC의 동료 1명, 기존 텍스트 채팅만 지원하는 구버전 상대 1명, 같은 확장 인스턴스로 연결하는 본인 대화.
- 작은 이미지, 가로·세로가 긴 이미지, EXIF 회전 정보가 있는 JPEG, 투명 PNG, GIF. WebP는 해당 시스템에 GdkPixbuf 로더가 있는 경우 포함합니다.
- 정상 디코딩 가능한 **10,485,760바이트** 이미지와 **10,485,761바이트** 이미지, 손상 이미지, 읽을 수 없는 이미지 파일.
- 파일 크기는 10MiB 이하이지만 픽셀 크기는 큰 정상 이미지. 임의로 파일 중간을 잘라 만든 손상 파일을 정상 크기 경계 시험에 사용하지 않습니다.

바이트 경계는 파일 관리자에 반올림되어 표시되는 MB 대신 `stat -c '%s %n' 파일명`으로 확인합니다. UI의 10 MB는 내부적으로 **10 × 1024 × 1024바이트(10MiB)**입니다.

필요하면 별도 터미널에서 `journalctl --user -f -o cat`으로 오류를 확인합니다. 수동 검증 기록에는 원본 이미지 내용, base64 데이터, 전체 개인 파일 경로, Intra 쿠키·토큰을 복사하지 않습니다.

## 정상 전송과 크기 경계

1. 업데이트된 동료와 텍스트를 주고받아 연결을 확인합니다. 채팅 입력칸에 보내지 않을 초안을 남깁니다.
2. 입력행의 이미지 버튼을 누릅니다. Shell 메뉴가 먼저 닫히고 파일 선택창을 정상적으로 클릭·탐색할 수 있어야 합니다. 선택 버튼은 **Send image**로 표시되어야 합니다.
3. 정상 이미지를 선택합니다. 선택 후 다른 앱의 포커스를 빼앗거나 Shell 메뉴를 자동으로 열지 않아야 합니다.
4. 직접 메뉴와 채팅을 다시 엽니다. 초안이 유지되고 이미지 말풍선에 파일명·크기·시각이 표시되어야 합니다. `Image queued for ...`는 큐 접수 안내이며, 상대 도착 여부는 상대 화면에서 별도로 확인합니다.
5. 정확히 **10,485,760바이트**인 정상 이미지가 전송되고 상대에게 한 번 표시되는지 확인합니다. 직후 양방향 텍스트도 계속 전달되어야 합니다.
6. **10,485,761바이트**인 정상 이미지는 크기 초과 안내와 함께 거부되어야 합니다. 상대 기록과 발신 이미지 기록에 추가되지 않아야 합니다.
7. 손상 파일, 읽기 실패, 지원하지 않는 이미지 형식을 각각 확인합니다. 실패 후 다른 정상 이미지를 다시 선택할 수 있어야 합니다.

선택 후 메뉴가 닫힌 상태에서 크기 초과·파일 읽기·디코딩 등의 오류가 발생하면 **Pingoose 알림 한 번**으로 알려야 합니다. 메뉴가 열려 있으면 인라인 오류 안내만 표시되어야 합니다. 오류 문구에 전체 경로나 원본 데이터가 나타나지 않아야 합니다. 일반 취소에는 오류 알림이 없어야 합니다.

## 원본 보존과 미리보기

| 파일 | 기대 결과 |
| --- | --- |
| 256×192보다 큰 일반 이미지 | 비율을 유지해 최대 256×192 안에 표시 |
| 256×192보다 작은 이미지 | 원본 크기보다 확대하지 않음 |
| 아주 긴 가로·세로 이미지 | 가로·세로 모두 프레임 경계를 넘지 않으며 원본 비율 유지 |
| EXIF 회전 JPEG | 회전 방향을 반영한 뒤에도 256×192 경계 유지 |
| 투명 PNG | 투명 영역과 실제 픽셀이 정상 표시 |
| GIF | 첫 프레임을 정적인 미리보기로 표시 |
| WebP | 시스템 로더가 있으면 표시, 없으면 처리 실패를 명확히 안내 |
| 큰 픽셀 크기·10MiB 이하의 정상 파일 | 고정된 원본 픽셀 상한 때문에 거부되지 않고, 디코딩 가능한 파일은 축소 미리보기 표시 |

256×192는 미리보기 제한이며 원본 전송 크기가 아닙니다. 큰 원본은 helper에서 처리하므로 Shell 메뉴·다른 앱이 계속 응답해야 합니다. 시스템 디코더 실패나 준비 시간 초과가 나면 실패 안내로 종료되고 다음 선택이 가능해야 합니다. 임의의 픽셀 크기 파일을 모두 처리할 수 있다는 의미로 판정하지 않습니다.

로딩 중, 미리보기 실패 후, 성공 후에 이미지 프레임 크기가 유지되어야 합니다. 파일명이 길거나 `<b>name</b>.png`처럼 보여도 markup으로 처리하지 않고 글자로 표시해야 합니다. 원본 바이트가 축소본으로 바뀌지 않는지는 소켓 검사의 payload 비교 결과와 함께 확인합니다. UI에는 원본 다운로드 기능이 없으므로 화면의 미리보기만으로 원본 바이트 동일성을 판정하지 않습니다.

## 파일 선택·대상 변경·취소

아래 항목을 **자동 패널 닫기 켜짐/꺼짐**에서 반복합니다.

- 파일 선택창을 연 뒤 충분히 기다립니다. 초기 메뉴 닫힘과 지연된 `menu-closed` 때문에 선택창이 곧바로 취소되지 않아야 합니다.
- 선택창의 Cancel 또는 Esc로 취소합니다. 이미지가 추가되지 않고 초안이 유지되며 오류 알림이 없어야 합니다.
- 선택 중 메뉴를 다시 엽니다. 첨부 버튼은 선택 대기 상태와 취소 동작을 제공하고, 두 번째 선택창이 동시에 열리지 않아야 합니다.
- 메뉴를 다시 연 뒤 닫거나 채팅 패널을 명시적으로 닫습니다. 진행 중인 선택은 취소되고 뒤늦게 완료해도 전송되지 않아야 합니다.
- A 대화에서 선택창을 연 뒤 B 대화로 바꿉니다. A에서 선택하던 파일이 B에게 전송되지 않아야 합니다. 대상을 바꾸지 않은 경우에만 원래 서비스·대상에 전송되어야 합니다.
- 선택 중 대상 연결 종료, 차단, 평가 만료, 계정 변경을 각각 확인합니다. 더 이상 허용되지 않는 상대에게 전송하지 않고 종료 이유를 안내해야 합니다.
- 선택 또는 미리보기 처리 중 확장을 비활성화합니다. 선택창과 helper가 종료되고, 다시 활성화해도 늦은 결과가 새 대화에 추가되지 않아야 합니다.
- 이미지 전송 도중 상대를 종료한 뒤 다시 연결합니다. 전송 중단 안내가 남고, 자동 재전송으로 같은 이미지가 반복 추가되지 않아야 합니다. 정상 텍스트와 새 이미지 전송을 다시 시도할 수 있어야 합니다.

## 구버전 동료와 호환성

구버전 상대와 먼저 텍스트를 양방향으로 주고받습니다. 새 버전에서 이미지 버튼을 눌렀을 때 양쪽 확장의 업데이트가 필요하다는 안내가 표시되고 이미지 전송이 시작되지 않아야 합니다. 이후에도 기존 텍스트 송수신과 연결 종료·재연결이 정상 동작해야 합니다.

구버전 상대와의 실패를 모든 이미지 전송 실패와 혼동하지 않도록, 같은 새 버전끼리의 정상 이미지 전송도 함께 확인합니다.

## 나에게 보내기

기존 채팅 연결 UI에서 본인의 로그인 또는 현재 좌석으로 연결하여 **같은 확장 인스턴스**와 통신합니다. 로그인 문자열만 같은 다른 PC는 이 검증의 자기 자신 대상이 아닙니다.

1. 텍스트를 한 번 보냅니다. 발신 말풍선이 하나만 생기고 같은 내용을 수신 말풍선으로 다시 추가하지 않아야 합니다.
2. 이미지를 한 번 보냅니다. 이미지와 미리보기도 한 번만 추가되어야 합니다.
3. 전송 직후 메뉴를 닫거나 다른 대화로 이동하는 경우에도 확인합니다. 본인 메시지 때문에 읽지 않은 수, 대화 배지, 채팅 수신 알림이 생기지 않아야 합니다.
4. 같은 이름을 쓰는 별도 PC에서 메시지를 보내는 확인이 가능하면 실제 수신 메시지는 정상 표시되는지 확인합니다. 본인에게 보내기 처리가 정상 상대의 메시지를 제거해서는 안 됩니다.
5. 본인 대화를 닫았다 다시 연결하고 반복합니다. 오래된 연결이나 기록 때문에 중복 표시가 되살아나지 않아야 합니다.

## 기록 메모리와 스크롤

이미지 원본 기록 합계는 전체 대화에서 **40MiB**입니다. 동시 전송 한도와 혼동하지 않도록 상대의 도착을 확인한 뒤 다음 파일을 보냅니다.

- 10MiB 이미지 4장을 순서대로 보내 합계 40MiB인 기록을 확인합니다. 다섯 번째 이미지를 보내면 오래된 이미지부터 `Image no longer kept in memory` 안내로 바뀌고 최신 이미지는 유지되어야 합니다. 여러 대화에 나누어 보낸 경우도 전체 합계에 따라 동작해야 합니다.
- 현재 보고 있는 이미지가 제거되더라도 말풍선 프레임·파일명·시각과 텍스트 기록이 남고 전체 대화를 다시 그리며 스크롤이 튀지 않아야 합니다.
- 마지막 메시지를 보고 있을 때 이미지 미리보기가 완성되면 아래쪽 보기를 유지해야 합니다. 위로 스크롤하여 이전 메시지를 읽고 있으면 미리보기 완료 때문에 맨 아래로 이동하지 않아야 합니다.
- 미리보기 여러 개를 처리하는 동안 패널을 닫았다 다시 엽니다. 닫힌 동안 작업을 중지하고 다시 열었을 때 필요한 미리보기를 표시해야 합니다. 빠르게 대화를 바꿔도 이전 대화의 이미지가 새 대화에 섞이지 않아야 합니다.
- 대화 종료, 로그아웃, 평가 만료, 확장 재시작 이후 관련 임시 대화 기록이 복원되지 않아야 합니다. 사용자가 선택한 원본 파일 자체는 그대로 남아야 합니다.

## 테마·좁은 화면·짧은 패널

Dark, Light, Pink, Halloween, Neon 각각에서 이미지가 있는 채팅을 열고 다음을 확인합니다.

- 첨부 버튼, 선택 대기 중 취소 아이콘, 파일명·크기·시각, 로딩·오류·기록 제거 안내가 배경과 구별되어 읽힙니다.
- 이미지 추가 전후에 기존 패널 너비·간격이 유지됩니다. 입력칸·전송·첨부 버튼이 서로 겹치지 않고 키보드로 접근할 수 있습니다.
- 채팅 높이를 줄이거나 낮은 해상도의 작업 영역에서 열어도 입력행과 닫기 버튼에 접근할 수 있습니다. 이미지 내용은 대화 스크롤 영역 안에서 움직여야 합니다.
- 패널을 늘리고 줄이면서 이미지·텍스트 선택·스크롤을 반복해도 원본 비율, 말풍선 모서리, 패널 가장자리와 resize 커서가 깨지지 않습니다.
- 배율 100%와 실제 사용하는 고배율, 투명도 0%와 80%에서 확인합니다. 테마·투명도 변경으로 저장한 높이·패널 간격·입력 초안이 바뀌지 않아야 합니다.

실패 기록에는 GNOME 버전, X11/Wayland, 확장 버전, 상대의 이미지 지원 여부, 테마·배율·저장 높이, 파일의 형식·바이트 수·픽셀 크기, 재현 순서와 해당 시각의 오류를 남깁니다. 이 체크리스트의 완료 여부와 자동 테스트 결과는 별도로 기록합니다.
